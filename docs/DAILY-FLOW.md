# การทำงานประจำวัน (Cron + OCR + LINE)

ระบบมีนาฬิกาปลุก 2 ชุด อยู่คนละที่ ปลุกคนละงาน

```
┌─ ชุดที่ 1: Supabase Cron (supabase/schedule.sql) ─────────
│ ปลุก → API บน Vercel
│ 23:35–00:00 ทุก 5 นาที : สแกน Drive + อ่าน QR → สร้างรายการสลิป
│ 08:00 / 08:05          : ส่ง Flex เข้า LINE (08:05 = ลองซ้ำถ้า 08:00 ล้มเหลว)
└──────────────────────────────────────────────────────────
┌─ ชุดที่ 2: GitHub Actions (.github/workflows/slip-ocr.yml) ─
│ ปลุก → คอมชั่วคราวของ GitHub (ไม่ผ่าน Vercel)
│ 01:30 (สำรอง 06:45) : อ่าน OCR สลิปที่ยังไม่มีร่าง
└──────────────────────────────────────────────────────────
```

แยก 2 ชุดเพราะ OCR (Paddle) ต้องใช้ Python ซึ่ง Vercel ไม่มี งานอื่นเป็น Node รันบน Vercel ได้

## ไล่ตามเวลา

### 23:30 มือถืออัปโหลด (ระบบเดิม ไม่อยู่ใน repo)
iPhone Shortcuts → Apps Script → `Expense/slips/<ธนาคาร>/<YYYY-MM-DD>/ไฟล์.jpg` (วันที่ = วันอัปโหลด)

### 23:35–00:00 ทุก 5 นาที: สแกน (ชุดที่ 1)
1. pg_cron ส่ง POST `{expense_api_url}/api/internal/tick` พร้อม `Bearer {expense_cron_secret}` (จาก Vault)
2. API ตรวจรหัสกับ `CRON_SECRET` → ขอกุญแจ `tick` (กันทำงานซ้อนกับปุ่มซิงก์และรอบอื่น)
3. สร้างงาน scan ให้แต่ละแหล่ง → ไล่ Drive ด้วย service account (อ่านอย่างเดียว) → ภาพใหม่เข้าตาราง `slips`
4. อ่าน QR ในเครื่อง → `needs_details` (รอข้อมูล) / `qr_unreadable` / `duplicate` (ซ้ำ)
5. ทำงานได้ราว 3 นาทีต่อรอบ ที่เหลือรอบถัดไปทำต่อ ไม่มีของใหม่ก็จบในไม่กี่วินาที
6. Cron ส่งช้าไม่เกิน 4 นาที (ถึง 00:04) ยังสแกน หลังจากนั้นไม่สแกนจนคืนถัดไป ไม่มีรอบสำรอง

### 01:30 และ 06:45: OCR (ชุดที่ 2)
1. GitHub เปิดคอม Ubuntu ชั่วคราว อ่านรหัสจาก GitHub Secrets
2. **เช็กก่อน**: มีสลิปที่ยังไม่บันทึก ไม่ซ้ำ ยังไม่มีร่าง (หรืออ่านพลาดไม่ถึง 3 ครั้ง) ไหม → ไม่มีก็จบ ไม่ติดตั้ง Paddle
3. มี → ติดตั้ง Paddle → อ่านทีละใบ (~15 วินาที) → แยกยอด วันเวลา ชื่อ เลขบัญชีที่ปิดบางส่วน → เขียน `slips.ocr_details`
4. อ่านชื่อเดือนไม่ออกแต่เลขวันตรงกับวันอัปโหลด → เติมเดือน/ปีจากวันอัปโหลด และติดป้ายให้ตรวจ
5. log มีแค่จำนวน (repo public) OCR ไม่สร้างรายการเงินเอง
6. GitHub อาจเริ่มรอบช้า รอบ 06:45 ทำแทนถ้า 01:30 ไม่ได้รัน

### 08:00: ส่ง Flex (ชุดที่ 1)
- ทุกวัน: สรุปเมื่อวาน · วันจันทร์: + สัปดาห์ก่อน · วันที่ 1: + เดือนก่อน · ย้อนหลังได้ไม่เกิน 7 วัน
- เนื้อหา: ใช้ไป (เฉพาะรายการที่บันทึกแล้ว ไม่นับโอนระหว่างบัญชี), แยกบัญชี, หมวดสูงสุด, รอข้อมูล N สลิป, ร่าง OCR ยังไม่ตรวจ ฿X (ไม่บวกเข้ายอด), โอนเข้าบัญชีตัวเอง N สลิป
- สลิปรอข้อมูลนับช่วงอัปโหลด 08:00 เมื่อวาน → 08:00 วันนี้
- ส่งผ่าน LINE Messaging API พร้อม retry key ไม่ส่งซ้ำ

### 08:05: ลองส่งซ้ำ
ส่ง 08:00 ไม่สำเร็จ → ลองที่ 08:05 → ยังไม่ได้ ลองรอบกลางคืน รวม 5 ครั้ง · ส่งครั้งแรกเกิน 23 ชั่วโมงแล้วหยุด กันข้อความซ้ำ

### ระหว่างวัน: ในแอป
- หน้าสลิป: ข้อมูล QR + ร่าง OCR + ป้าย "น่าจะโอนเข้าบัญชีตัวเอง" / "เติมจากวันอัปโหลด"
- ฟอร์มบันทึกเติมให้: ยอด วันเวลา ประเภท (โอน ถ้าเลขบัญชีหรือชื่อผู้รับตรงกับของคุณ) บัญชีต้นทาง/ปลายทางจากเลขบัญชี — คุณกดยืนยันเองทุกครั้ง
- ปุ่ม **ซิงก์ตอนนี้**: สแกนทันที ไม่ต้องรอ Cron (รอบละ 60 วินาที แอปเรียกต่อเองจนเสร็จ สูงสุด 10 รอบ) ถ้า Cron กำลังทำงานจะแจ้งและไม่ทำซ้อน

## รหัสลับอยู่ที่ไหน

| ที่เก็บ | ชื่อ |
|---|---|
| Supabase Vault | `expense_api_url`, `expense_cron_secret` |
| Vercel | `CRON_SECRET` (= `expense_cron_secret`), `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, `GOOGLE_SERVICE_ACCOUNT_EMAIL`, `GOOGLE_PRIVATE_KEY`, `DRIVE_OWNER_ID`, `LINE_CHANNEL_ACCESS_TOKEN`, `LINE_CHANNEL_SECRET`, `APP_ORIGIN`, `OCR_ENABLED=false` |
| GitHub Secrets | `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, `GOOGLE_SERVICE_ACCOUNT_EMAIL`, `GOOGLE_PRIVATE_KEY`, `DRIVE_OWNER_ID` |

## ถ้ามีอะไรพัง

| ปัญหา | ระบบทำอะไร |
|---|---|
| มือถือไม่อัปโหลด 23:30 | ไม่มีรอบสำรอง กด "ซิงก์ตอนนี้" หรือรอคืนถัดไป |
| สลิปเยอะสแกนไม่ทัน | รอบ 5 นาทีถัดไปทำต่อ ถึง 00:00 |
| GitHub เริ่ม 01:30 ช้า/ข้าม | รอบ 06:45 ทำแทน |
| OCR อ่านพลาด | ลองใหม่สูงสุด 3 ครั้ง แล้วกรอกเอง |
| LINE ล่มตอน 08:00 | ลองใหม่ 08:05 และรอบกลางคืน |
| Cron/Vercel ล่มทั้งวัน | รอบ 08:00 ถัดไปส่งย้อนหลังไม่เกิน 7 วัน |

## เวลาใน cron เป็น UTC
ไทย = UTC+7 เช่น `35-55/5 16 * * *` = นาที 35–55 ทีละ 5 ของชั่วโมง 16 UTC = 23:35–23:55 ไทย · `tests/schedule.test.ts` ตรวจว่า `schedule.sql` ตรงกับตัวเช็กเวลาในโค้ด
